Agent Bench Tech Report 框架

结构讨论稿 v0.2 · 英文章节名 + 中文说明 · 尚未填写正文

先决定这是“benchmark 研究报告”，还是“平台设计与初步验证报告”。下面以 10 页正文作为讨论起点，不要求现在填满，也不固定最终页数。

章节与建议页数

部分 建议页数 正文占比 当前建议
Abstract 0.5 5% 保留位置，最后写
1. Introduction 1.0 10% 必需
2. Related Work 0.5 5% 可并入引言
3. Benchmark Design 2.0 20% 核心
4. Evaluation Protocol 1.5 15% 核心
5. System Implementation 1.0 10% 可压缩或部分移至附录
6. Experiments and Analysis 2.0 20% 核心预留，暂不填结果
7. Limitations and Reproducibility 1.0 10% 保留关键边界
8. Conclusion 0.5 5% 保留位置，最后写
合计 10.0 100% 参考文献、附录另计

若以模型比较为核心，可以增加实验篇幅，压缩实现细节；若以平台为核心，可以增加系统设计和验证。先定主线，再调配额。

Abstract

要回答的问题： 解决什么问题、提供什么、最终证明了什么？

候选内容： [研究问题]、[方法或 benchmark 概要]、[关键证据与结论]。

图表或证据： 从确定后的主结果提炼，不单独放图。

待决定： 突出哪一条主张？正文与实验范围确定前保持空白。

1. Introduction

要回答的问题： 为什么需要这个 benchmark？

候选内容： [研究动机]、[主要研究问题与相关缺口]、[最多三项贡献]。

图表或证据： 候选图 1：[项目整体概念图]。

待决定： 核心贡献来自任务设计、评测方法、系统实现还是实验发现？哪些工程功能值得成为研究贡献？

2. Related Work

要回答的问题： 与最相关的已有工作有何区别？

候选内容： [相关机器人 benchmark]、[相关 agent 研究]、[按明确维度组织的差异]。

图表或证据： 可选：[相关工作对照表]，每项比较需有来源。

待决定： 哪两三类研究与主线真正相关？是否需要独立章节？不预填优越性结论。

3. Benchmark Design

要回答的问题： 哪些任务能测量目标能力，为什么选择它们？

候选小节：

  • 3.1 [Problem Formulation / 目标能力与任务定义]
  • 3.2 [Task Families / 任务家族与纳入范围]
  • 3.3 [Embodiments and Variations / 机器人与任务变体]

图表或证据： 候选图 2：[任务家族与能力对应图]；可选表：[任务范围与计数口径]。

待决定： 哪些任务正式纳入，哪些是扩展或原型？机器人、种子与观测设置如何计数？正文展示哪些代表案例，完整列表是否进附录？

4. Evaluation Protocol

要回答的问题： 如何控制输入、工具、预算和评分，使结果可比较？

候选小节：

  • 4.1 [Agent Interface and Permissions / 观测、动作与工具权限]
  • 4.2 [Success Criteria and Metrics / 成功、失败与报告指标]
  • 4.3 [Experimental Conditions / 初态、种子、预算与重复试验]

图表或证据： 候选图 3：[一次评测的交互与评分流程]；可选表：[评测设置对照]。

待决定： 哪些规则跨任务共享，哪些分别说明？如何记录重试、缺失试验与失败？权限等级名称和具体数值暂不写死。

5. System Implementation

要回答的问题： 评测如何运行，并保留可复核的记录？

候选内容： [agent、环境与评测器的职责]、[执行接口和数据流]、[必要的记录、隔离或回放机制]。

图表或证据： 可选：[系统架构图]；若与图 3 重复则合并。

待决定： 哪些机制属于核心贡献？SDK 方法、动作单位、安装步骤和日志字段是否移至文档或附录？不默认所有环境共用同一实现。

6. Experiments and Analysis

要回答的问题： 哪些实验回答研究问题，哪些结果支持贡献？

候选小节：

  • 6.1 [Setup / 被测 agent、基线与固定配置]
  • 6.2 [Main Results / 主要比较]
  • 6.3 [Ablations or Failure Analysis / 关键消融或失败分析]

图表或证据： 候选表 1：[主结果表，不填数值]；候选图/表 4：[关键消融或失败分类]。

待决定： 第一版回答哪 1–3 个实验问题？比较哪些 agent、工具设置与任务子集？哪些结果已有，哪些需要新实验？

保留不同证据的槽位：[系统功能验证]、[参考控制器执行]、[被测模型表现]。是否全部纳入正文待定，不能合并成一个成绩。暂不默认需要排行榜或大规模消融。

7. Limitations and Reproducibility

要回答的问题： 结论适用于什么范围，其他研究者如何复现？

候选内容： [任务覆盖与机制假设]、[影响结论的版本和配置]、[最低复现要求与资源入口]。

图表或证据： 可选：[复现配置表]，完整清单可进附录。

待决定： 哪些限制会改变结果解释，必须出现在正文？首次发布提供哪些资源？

8. Conclusion

要回答的问题： 读者应带走哪一项已被证据支持的结论？

候选内容： [研究问题的回答]、[主要贡献]、[最直接的后续方向]。

图表或证据： 不新增结果。

待决定： 等主结果与范围确定后再写，不提前承诺通用能力或泛化结论。

可选附录

  • [完整任务清单与环境细则]
  • [接口、动作语义与部署说明]
  • [完整实验配置与补充结果]
  • [代表轨迹、失败案例与证据索引]

这些只是候选，不要求全部加入。参考文献随最终纳入的内容补齐。

与网站的对应关系

报告内容 网站呈现方式
引言与贡献 首屏一句定位 + 少量贡献摘要
Benchmark Design 少量代表任务与画面
Evaluation Protocol 一张流程图 + 关键条件
System Implementation 仅保留解释主张所需的部分
Experiments and Analysis 一张主结果图 + 1–2 条发现
附录与复现细节 链接，不搬到首页

网站不需要与报告每节一一对应。先确定主张与证据，再选择适合首页展示的内容。
